# 0014 — 고유 ID 부여, max(ids)+1 vs len(notes)+1

## 무엇을 했나
`notes.py`에 `next_id(notes)` 함수를 추가하고, `add_note`가 새 노트에 `"id": next_id(notes)`를
붙이도록 고쳤다. title 중복 문제(레슨 9~10에서 스스로 발견했던 버그)를 임시방편(검색 결과에
번호 매기기)이 아니라 근본적으로 해결하는 방향.

## 겪은 실수와 fix
1. `next_id`를 처음에 `notes_app.py`에 정의해서, `notes.py`의 `add_note`에서 `undefined name
   'next_id'` 에러가 났다. 두 파일이 import로 연결돼 있어도 함수가 정의된 파일 안에서만 그 이름이
   보인다는 걸(레슨 11의 모듈/이름공간 감각과 동일 맥락) 다시 짚었다. `next_id`를 `notes.py`로
   옮겨서 해결 — `notes_app.py`의 중복 정의도 스스로 지웠다.
2. `return max(ids) + 1`이 `for` 루프 안(첫 원소 처리 직후)에 들여쓰기 돼 있어서, 리스트를 다 순회하기도
   전에 첫 노트의 id만 보고 함수가 끝나버리는 버그가 있었다. 들여쓰기를 `for` 블록 밖으로 빼야 한다는 걸
   스스로 알아채고 고쳤다.

## 확인한 개념
- **`len()`**: 리스트의 "지금 남아있는 개수"를 반환하는 내장 함수. "지금까지 몇 번 추가했는지"와는
  다르다는 게 핵심 — 삭제가 끼면 두 값이 어긋난다.
- **`max(ids) + 1` vs `len(notes) + 1`**: `len()` 기반은 삭제 후 재사용 시 이미 쓰인 id와 겹칠 수 있다는
  것을, 왜 겹치는지("id는 과거 이력을 보존해야 하는데 len은 현재 개수만 본다")까지 자기 말로 정확히
  설명함 — 실제로 삭제→재추가 테스트(id 1 삭제 후 재추가 시 3이 나옴, 1이나 2로 겹치지 않음)로 검증했다.

## Implications
- 고유 ID 개념과 "왜 len이 아니라 max+1인지"는 다음에 다시 설명할 필요 없음
- 아직 `find`/`delete` 메뉴는 title 기준 그대로 — id로 검색·삭제하도록 바꾸는 리팩터링은 다음 세션 후보
- 세션 중 "타입스크립트 vs 파이썬을 왜 배우는지" 질문이 나옴 — `ai-dev-team`의 `decisions.md`가 이미
  `claude-agent-sdk-python`(파이썬)을 채택했다는 근거로 답변함. 미션에 이미 반영된 내용이라 MISSION.md
  변경은 불필요.
