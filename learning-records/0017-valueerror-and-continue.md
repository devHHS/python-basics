# 0017 — ValueError 처리와 continue의 스코프 이해

## 무엇을 했나
레슨 15에서 `int(input(...))`이 숫자로 못 바꿀 값(문자, 특수문자, 빈칸, 빈 문자열 등)을 만나면 전부
동일한 `ValueError`로 처리된다는 걸 실제 파이썬 실행 결과로 확인한 뒤, `notes_app.py`의 Update(3번)와
Delete(4번-1번) 두 곳에 `try/except ValueError` + `continue`를 스스로 작성해 정확히 고쳤다.

## 확인한 개념
- **한 종류의 에러가 여러 원인을 포괄한다는 것**: 처음엔 "문자열/대문자/특수문자/빈칸마다 다르게 처리해야
  하는 것 아니냐"고 질문했으나, `int()`가 실패 원인과 무관하게 항상 `ValueError` 하나만 던진다는 걸
  실행 결과로 확인하고 이해함. "왜 종류별로 안 나누는가"를 스스로 묻고 답을 찾은 과정이 의미 있음.
- **continue의 스코프**: `continue`가 몇 겹의 `if` 안에 있든 상관없이, 자신을 감싸는 가장 가까운
  *반복문*(`while`/`for`)으로 돌아간다는 걸 정확히 이해함. "if 블록을 반복문 밖으로 옮겨도 결과가
  같겠냐"는 질문에 "똑같다"고 정확히 답해, 들여쓰기 깊이가 아니라 반복문 소속 여부가 기준이라는 걸
  확실히 짚어냄.

## Implications
- 예외 처리에서 "에러 종류(exception type) vs 에러 원인(root cause)"을 구분하는 감각이 생겼다 —
  나중에 여러 `except` 절을 쓰는 경우(예: `ValueError` vs `KeyError`)를 배울 때 "왜 나누는가/왜
  하나로 합치는가"를 스스로 판단할 토대가 됨.
- `continue`/`break`의 스코프 규칙은 중첩 반복문(`for` 안에 `for` 등)을 다룰 때 다시 확실히 짚을
  필요가 있음 — 지금은 반복문이 하나뿐인 구조에서만 확인함.

  유닛 테스트 작성.
