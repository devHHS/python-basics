# try/except로 파일 없음 방어 + 읽기-추가-쓰기 순서 이해

`notes_app.py`에서 `try/except FileNotFoundError`로 파일이 없을 때도 안 터지게 만들었고, 직접 파일을 지웠다 복원하며 두 경로(있음/없음) 모두 테스트했다. 이후 "w" 모드로 파일을 열면 즉시 내용이 비워진다는 것과 `json.dump(obj, fp)`가 인자 2개를 받는다는 것을 스스로 설명했고, 잘못된 순서(쓰기 → 추가 → 읽기)를 읽기 → 입력 → 추가 → 쓰기 순서로 직접 재배열했다.

**Implications**: 파일 I/O에서 "열기만 해도 부작용이 생길 수 있다"(w 모드가 즉시 비움)는 점과 연산 순서의 중요성을 체감했다. 다음 레슨은 이 위에 조금 더 쌓을 수 있는 것 — 예: 여러 함수로 더 쪼개기(읽기/쓰기를 각각 함수로), 또는 사용자 입력 검증(빈 제목 막기) 정도가 적절한 난이도.
