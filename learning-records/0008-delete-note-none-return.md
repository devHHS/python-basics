# delete_note가 항상 notes를 리턴해서 None 체크가 무의미했던 버그

레슨 7(None 체크하기)을 적용하면서, `choice == "2"`(찾기)는 `find_note` 결과를 `if found is None:`으로
잘 구분했다. `choice == "3"`(삭제)도 같은 패턴으로 `if found is None:`을 썼지만, 실제로는
`delete_note`가 찾았을 때도 `return notes`, 못 찾았을 때도 `return notes`를 리턴하고 있어서
`None`이 될 수가 없었다 — 즉 검증 코드는 있는데 실제로는 항상 "성공"으로 찍히는 상태였다.

존재하지 않는 제목(`9999999999`)으로 직접 삭제를 시도해보게 하자 "9999999999 is deleted"가 찍히는 걸
스스로 확인했고, "왜 그런지 네 말로 설명해봐"라는 질문에 "둘 다 그냥 notes를 리턴해서 구분이 안 된다"고
정확히 짚어냈다. 이후 `delete_note`의 못 찾은 경우를 `return None`으로 직접 고쳐서 해결했다.

**Implications**: "if로 None을 확인한다"는 문법 자체는 레슨 7에서 이미 습득했다. 이번에 부족했던 건
"함수가 애초에 그 값을 구분해서 리턴하는지"까지 확인하는 습관 — 검증 코드가 있다고 안심하지 말고,
실패 케이스(존재하지 않는 값)로 직접 테스트해보는 태도가 버그를 잡아냈다. 다음에도 "이 함수가 정말
성공/실패를 구분해서 리턴하는가"를 먼저 확인하게 유도하면 좋을 것 같다. 또한 복붙 후 수정 누락(레슨 7
직접 해보기에서 3번 블록에 `find_note`를 그대로 복붙했던 것)이 반복됐는데, 매번 실제로 실행해서 확인하는
습관이 이를 잘 잡아내고 있다.
