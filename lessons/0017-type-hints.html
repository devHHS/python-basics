타입 힌트 (type hints)

지금까지 def next_id(notes):처럼 매개변수에 어떤 타입의 값이 와야 하는지는 주석이나 변수 이름으로만 짐작해왔다. 타입 힌트는 "이 매개변수는 이런 타입, 반환값은 저런 타입"을 코드에 직접 적어두는 문법이다. 파이썬은 이걸 강제하지 않는다 — 틀려도 실행은 된다. 하지만 에디터와 사람이 함수를 읽을 때 바로 알 수 있고, 나중에 배울 Pydantic(ai-dev-team에서 쓸 라이브러리)이 데이터 검증에 쓰는 문법이 바로 이 타입 힌트를 확장한 것이다.

중요: 타입 힌트는 강제가 아니다. def f(x: int): return x에 f("hello")를 넣어도 파이썬은 에러를 내지 않는다. 타입 힌트는 실행 규칙이 아니라 "약속"이고, 이 약속을 실제로 검사해주는 게 나중에 배울 Pydantic 같은 도구다.

핵심 개념 1 — 변수와 함수 매개변수

title: str = "장보기"
count: int = 3
price: float = 9.99
done: bool = False

함수에서는 매개변수 이름 뒤에 : 타입을 붙이고, 반환값 타입은 -> 타입으로 괄호 뒤에 적는다. 

def add(a: int, b: int) -> int:
    return a + b

핵심 개념 2 — list와 dict 안의 타입

notes.py의 notes는 "딕셔너리들의 리스트"다. 이럴 때는 list[dict]처럼 대괄호로 안에 뭐가 들었는지 적는다. 

def find_all_notes(notes: list[dict]) -> list[dict]:
    return notes

핵심 개념 3 — "이거나 None"은 | None

find_note_by_id는 찾으면 dict, 못 찾으면 None을 돌려준다(레슨 7). 이렇게 "이 타입이거나 None"을 표현할 때는 |(파이프)를 쓴다. 

def find_note_by_id(notes: list[dict], id: int) -> dict | None:
    for n in notes:
        if n["id"] == id:
            return n
    return None
Primary source Python 공식 문서 — typing 모듈 — 타입 힌트 전체 문법의 공식 레퍼런스. 지금은 위 세 가지(기본 타입, list[X], X | None)만 알면 충분하고, 나머지는 필요할 때 찾아보면 된다.

확인 퀴즈

1. 타입 힌트를 틀리게 써도 프로그램이 실행되는 이유는?
2. "딕셔너리들의 리스트"를 타입 힌트로 쓰면?
3. "dict이거나 None"을 반환 타입으로 쓰면?

직접 해보기

  1. notes.py를 열어서 next_id(notes)에 타입 힌트를 붙인다 — 매개변수는 list[dict], 반환값은 무엇일지 함수 본문을 보고 직접 정한다
  2. find_note_by_id(notes, id)에도 타입 힌트를 붙인다 — id는 어떤 타입인지, 반환값은 dict만 나올 수 있는지 아니면 다른 것도 나올 수 있는지 함수 본문을 다시 읽고 정한다
  3. 타입 힌트를 붙인 뒤 pytest를 다시 돌려서 여전히 다 통과하는지 확인한다 — 타입 힌트만 추가했다면 동작은 하나도 안 바뀌어야 정상이다
  4. 일부러 id: str처럼 실제와 다른 타입 힌트를 써보고, 그래도 함수 호출과 테스트가 멀쩡히 되는지 확인해본다 — "강제가 아니다"를 코드로 직접 겪어본다. 확인 후 원래 타입으로 되돌린다

막히면 정답을 바로 묻기보다, "지금 뭐가 안 되는지"와 "왜 그런 것 같은지"부터 말해보자. 그게 이 폴더의 핵심 학습 목표(에러 읽는 법)다.
