클래스 — 딕셔너리 대신 "정해진 모양"으로 데이터 묶기

지금까지 노트를 {"title": title, "content": content} 딕셔너리로 표현했어. 잘 작동했지만 문제가 하나 있다 — 딕셔너리는 아무 키나 넣을 수 있어서, 실수로 note["titel"]처럼 오타를 내도 파이썬은 에러를 내지 않고 그냥 새 키를 만들어버린다. 클래스(class)는 "이 데이터는 항상 이런 모양이다"를 미리 정해두는 방법이다.

왜 필요할까? ai-dev-team에서 쓸 Pydantic이라는 도구는 클래스를 기반으로 "이 데이터는 반드시 이런 필드를 가져야 한다"를 강제한다. 클래스 문법에 먼저 익숙해지는 게 그걸 이해하는 가장 빠른 길이다.

핵심 개념 — class, __init__, self

클래스는 "이런 모양의 물건을 만드는 설계도"야. Note라는 설계도를 만들어보자: 

class Note:
    def __init__(self, title, content):
        self.title = title
        self.content = content

하나씩 뜯어보면:

  • class Note: — "Note"라는 이름의 새 설계도를 만든다.
  • def __init__(self, title, content): — 이 설계도로 물건(인스턴스)을 만들 때 자동으로 실행되는 함수다. 이름이 정해져 있다(__init__, 앞뒤로 언더스코어 2개씩).
  • self — "지금 만들어지고 있는 바로 이 물건"을 가리킨다. 함수를 부를 때 직접 넘기지 않아도 파이썬이 자동으로 채워준다.
  • self.title = title — 넘겨받은 title 값을, 지금 만들어지는 이 물건의 title이라는 자리에 저장한다.

이제 이 설계도로 실제 노트를 만들어보자:

n = Note("장보기", "우유, 계란")
n.title    # "장보기"
n.content  # "우유, 계란"

딕셔너리는 n["title"]처럼 대괄호로 접근했지만, 클래스로 만든 물건은 n.title처럼 점(.)으로 접근한다. 이미 notes.add_note(...)에서 점 표기법을 써봤지? 그거랑 똑같은 문법이다 — 모듈의 함수를 부르는 것도, 인스턴스의 속성에 접근하는 것도 "점 뒤에 원하는 이름"이라는 같은 규칙을 쓴다.
