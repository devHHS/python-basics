None 확인하기 — 함수가 진짜 뭘 돌려줬는지 보기

지난 세션에 이런 코드가 있었어: 

print(find_note(notes, title))
print(f"{title}을 성공적으로 찾았습니다")

문제는, find_note가 None(못 찾았다는 뜻)을 돌려줘도 두 번째 줄은 무조건 "성공적으로 찾았습니다"라고 찍힌다는 거야. 함수 호출과 출력 메시지를 분리한 건 맞았는데(레슨 6 이후 배운 것), 그 결과를 확인하지는 않은 거지. 이번 레슨에서 그 구멍을 메운다.

왜 필요할까? 함수를 호출하는 것과, 그 함수가 무엇을 돌려줬는지 확인하고 그에 따라 다르게 반응하는 것은 다른 일이야. 지금까지는 "호출하면 끝"이었는데, 앞으로 ai-dev-team에서 에이전트가 "작업이 성공했는지 실패했는지"에 따라 다음 행동을 바꾸려면 이 패턴이 기본이 된다.

핵심 개념 1 — None은 "값이 없다"는 값

None은 파이썬에서 "아무 값도 없다"를 나타내는 특별한 값이야. find_note를 다시 보자: 

def find_note(notes, title):
    for n in notes:
        if n["title"] == title:
            return n
    return None

제목이 일치하는 노트를 찾으면 그 노트(딕셔너리)를 return하고, 끝까지 못 찾으면 마지막 줄의 return None이 실행돼. 즉 find_note(...)의 결과는 "노트 딕셔너리 하나" 아니면 "None", 둘 중 하나야.

사실 return을 아예 안 쓰고 함수가 끝까지 실행돼도 파이썬은 자동으로 None을 돌려줘. return None을 명시적으로 쓴 건 "여기서 못 찾았다"는 의도를 코드로 드러낸 것.

핵심 개념 2 — if로 결과를 확인한 다음 반응하기

결과를 변수에 담아두고, if로 그 값이 None인지 확인한 다음 다르게 반응하면 돼: 

found = find_note(notes, title)
if found is None:
    print(f"{title}을 찾지 못했습니다")
else:
    print(f"{title}을 성공적으로 찾았습니다: {found}")

found == None이 아니라 found is None을 쓴 걸 눈여겨봐. None은 "어떤 값과 같다/다르다"보다 "그 자체로 유일한 존재인지"를 물어보는 게 더 정확해서, 파이썬에서는 None 비교에 is를 쓰는 게 관례야.

확인 퀴즈

1. 함수가 아무것도 못 찾았을 때 관례적으로 돌려주는 값은?
2. 어떤 값이 None인지 확인할 때 파이썬에서 권장하는 비교는?
3. found가 None일 때 "찾지 못했습니다"를 찍으려면 어느 블록에 넣어야 할까?

직접 해보기

notes_app.py의 choice == "2" 블록(찾기)을 고쳐보자:

  1. find_note(notes, title)의 결과를 변수(예: found)에 담는다
  2. if found is None:이면 "찾지 못했습니다" 같은 메시지를 찍는다
  3. else:이면 "성공적으로 찾았습니다"와 함께 found의 내용(제목/내용)을 찍는다

다 되면 여유가 있을 때 choice == "3"(삭제)도 같은 방식으로 고민해봐. 다만 지금 delete_note는 못 찾아도 notes를 그대로 돌려주기 때문에 find_note처럼 None으로 구분이 안 돼 — 이 부분은 함수 자체를 손봐야 할 수도 있는데, 오늘은 거기까지 안 가도 괜찮다. 먼저 2번(찾기)만 확실히 되는 것부터.
