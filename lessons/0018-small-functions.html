Lesson 0018 · Python 기초 · SE 기초

함수를 작게 쪼개는 이유

지금까지는 문법 위주로 배웠다면, 이번엔 소프트웨어 엔지니어링(SE) 기초다. notes_app.py를 열어서 메뉴 2번(Find) 안을 보자. "1. Find by title"과 "2. Find all" 두 분기에 아래 코드가 토씨 하나 안 틀리고 그대로 두 번 나온다. 

for n in found_notes:
    print(f"ID:{n['id']} | title:{n['title']} | content:{n['content']}")
질문: 나중에 출력 형식을 바꾸고 싶어졌다고 해보자 — 예를 들어 content가 너무 길면 잘라서 보여주고 싶다. 코드를 몇 군데 고쳐야 할까? 만약 두 곳 중 한 곳만 고치고 깜빡한다면 무슨 일이 벌어질까? (레슨 14에서 겪었던 "조용히 실패하는 버그"를 떠올려보자.)

핵심 개념 1 — 중복 코드(DRY)의 위험

같은 지식(여기서는 "노트를 어떻게 출력할지")이 코드 안에 여러 곳 흩어져 있으면, 그 지식이 바뀔 때마다 모든 자리를 빠짐없이 고쳐야 한다. 하나라도 놓치면 두 화면이 서로 다르게 동작하는 버그가 생긴다. 이걸 DRY(Don't Repeat Yourself) 원칙이라고 부른다 — "같은 지식은 한 곳에만 있어야 한다."

핵심 개념 2 — 함수로 뽑으면 한 곳만 고치면 된다

중복된 코드를 함수로 뽑아내는 것을 Extract Method(메서드/함수 추출)라고 한다. 반복되던 코드를 이름 붙은 함수 하나로 만들고, 원래 있던 자리에서는 그 함수를 호출만 하도록 바꾸는 것이다. 

def print_notes(notes_list: list[dict]) -> None:
    for n in notes_list:
        print(f"ID:{n['id']} | title:{n['title']} | content:{n['content']}")

이렇게 뽑아두면 출력 형식을 바꿀 일이 생겨도 print_notes 함수 한 곳만 고치면 된다. 덤으로 print_notes(...)라는 이름만 봐도 "아, 노트 목록을 출력하는구나"를 바로 알 수 있다 — 코드가 더 읽기 쉬워진다.

핵심 개념 3 — 작은 함수와 테스트

레슨 16~20에서 notes.py의 함수들을 pytest로 테스트했다. 그게 가능했던 이유는 그 함수들이 값을 받아서(매개변수) → 계산하고 → 돌려주기(return)만 했기 때문이다. 반면 print_notes는 화면에 출력만 하고 아무것도 return하지 않는다 — assert로 확인할 "결과값"이 없다는 뜻이다. 함수를 작게 쪼개면, 이렇게 "테스트하기 쉬운 순수 계산"과 "테스트하기 어려운 화면 출력"을 자연스럽게 분리할 수 있다.

Primary source Refactoring.Guru — Extract Method — 오늘 할 리팩터링의 정식 이름과 절차. "더 읽기 쉬운 코드, 중복 제거, 에러 예방"이 이 리팩터링의 목적이라고 설명한다.

확인 퀴즈

1. 똑같은 코드가 여러 군데 반복될 때 가장 위험한 이유는?
2. 중복 코드를 함수로 뽑아낸 뒤에도 프로그램의 동작이 이전과 똑같아야 하는 이유는?
3. print_notes 같은 함수를 notes.py의 함수들처럼 pytest로 테스트하기 어려운 이유는?

직접 해보기

  1. notes_app.py에서 완전히 똑같은 두 줄짜리 코드가 반복되는 자리 두 곳을 직접 찾아본다 (힌트: 메뉴 2번 안)
  2. 그 코드를 print_notes(notes_list: list[dict]) -> None이라는 이름의 함수로 뽑아내 notes_app.py 파일 위쪽(다른 함수/로직 시작 전)에 정의한다
  3. 원래 코드가 있던 두 자리를 각각 print_notes(found_notes) 호출로 바꾼다
  4. python3 notes_app.py로 직접 실행해서 메뉴 2번의 두 분기가 이전과 똑같이 동작하는지 확인한다 — 동작이 하나도 안 바뀌어야 정상이다(그게 리팩터링이다)
  5. 생각해보기: print_notes를 pytest로 테스트하려면 뭐가 걸림돌인지, notes.py의 함수들과 뭐가 다른지 자기 말로 설명해본다 (정답을 맞히는 게 아니라 차이를 스스로 짚어보는 연습)

막히면 정답을 바로 묻기보다, "지금 뭐가 안 되는지"와 "왜 그런 것 같은지"부터 말해보자. 그게 이 폴더의 핵심 학습 목표(에러 읽는 법)다.
