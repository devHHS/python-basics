리팩터링 — find/delete를 title 대신 id 기준으로

레슨 13에서 모든 노트에 고유한 id를 붙였다. 그런데 정작 메뉴의 검색(2번)과 삭제(3번)는 아직 title로 동작한다 — title이 중복될 수 있다는 문제(레슨 9~10)를 find_all_by_title + "몇 번째 걸 고를래?" 방식으로 우회하고 있다. 이제 id가 있으니 그 우회로가 필요 없다.

새 문법은 없다. 이 레슨은 함수(def), for, if, int() 변환처럼 이미 아는 것들을 다시 조합해서, "문제(title 중복)가 근본적으로 해결됐으니 그걸 우회하던 코드도 걷어낸다"는 소프트웨어 엔지니어링 감각을 연습하는 자리다.

핵심 개념 1 — id로 찾는 함수

notes.py에 이미 있는 find_note(notes, title)를 다시 보자: 

def find_note(notes, title):
    for n in notes:
        if n["title"] == title:
            return n
    return None

title 대신 id로 찾으려면 비교하는 조건 하나만 바꾸면 된다. 어떻게 바꿔야 할지 직접 생각해보고 find_by_id(notes, note_id) 함수를 만들어보자.

핵심 개념 2 — id는 항상 int, input()은 항상 str

레슨 5에서 find_note(notes, 6)이 안 되고 find_note(notes, "6")이 돼야 했던 이유를 기억할 것이다 — input()은 항상 문자열을 돌려준다. 반대로 next_id가 만든 id는 정수(int)다. 그러니 사용자가 입력한 id를 find_by_id에 넘기기 전에 int(input(...))로 변환해야 한다. 같은 문제를 방향만 바꿔서 다시 만나는 셈이다.

Primary source Python 공식 문서 — int() — 문자열을 정수로 바꿀 때의 정확한 동작(변환 안 되면 어떤 에러가 나는지도) 확인해봐.

확인 퀴즈

1. find_by_id를 find_note에서 만들 때 바꿔야 하는 것은?
2. input()으로 받은 id를 find_by_id에 바로 넘기면 왜 못 찾을까?
3. id 기준으로 바꾸면 find_all_by_title + 번호 선택 방식이 왜 필요 없어지나?

직접 해보기

notes.py와 notes_app.py에서 진행한다. 작은 단계로 나눠서, 매 단계마다 실행해보며 확인한다:

  1. notes.py에 find_by_id(notes, note_id) 함수를 find_note를 참고해서 직접 작성한다
  2. notes_app.py의 2번(Find) 메뉴를 고친다 — title 대신 "ID: "를 물어보고, int(...)로 변환한 뒤 find_by_id로 찾아서 결과를 출력한다. (title이 여러 개 나올 수 있던 예전 구조 — find_all_by_title, 번호 선택 — 는 이제 필요 없으니 걷어낸다)
  3. 3번(Delete)도 같은 방식으로 고친다 — id를 물어보고 find_by_id로 찾은 뒤, 찾았으면 notes.remove(...)로 지운다. "1. Delete one 2. Delete all with this title" 서브메뉴도 title 중복 때문에 있던 거라 이제 단순화할 수 있는지 생각해보자
  4. 4번(Update)도 title 대신 id로 찾도록 바꾼다
  5. 노트 몇 개를 추가하고, id로 검색/수정/삭제가 잘 되는지 notes_app.py를 실행해서 직접 확인한다

막히면 정답을 바로 묻기보다, "지금 뭐가 안 되는지"와 "왜 그런 것 같은지"부터 말해보자. 그게 이 폴더의 핵심 학습 목표(에러 읽는 법)다.
