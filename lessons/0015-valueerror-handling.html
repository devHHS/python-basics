ValueError 처리 — 숫자가 아닌 ID를 입력하면 죽는 버그 고치기

레슨 2에서 try/except로 FileNotFoundError를 잡아본 적이 있다. 그런데 notes_app.py에는 아직 못 잡은 에러가 하나 더 있다 — 3번(Update), 4번(Delete) 메뉴에서 ID를 물어볼 때, 숫자가 아닌 걸 입력하면 프로그램이 그 자리에서 죽는다.

새 문법은 try/except 하나뿐이다. 레슨 2에서 배운 것과 똑같은 구조를, 다른 종류의 에러(ValueError)에 다시 적용해보는 레슨이다.

핵심 개념 — int()가 못 바꾸면 ValueError

int(input(...))은 사용자가 입력한 문자열을 정수로 바꾼다. 그런데 "abc"처럼 숫자로 바꿀 수 없는 문자열을 넣으면 어떻게 될까? 파이썬 인터프리터에게 직접 물어보자: 

>>> int("abc")
Traceback (most recent call last):
  ...
ValueError: invalid literal for int() with base 10: 'abc'

ValueError는 "타입은 맞는데(문자열은 문자열이다) 값이 이상해서 원하는 걸 못 만든다"는 뜻의 에러다. FileNotFoundError를 잡을 때처럼, try 블록 안에 위험한 코드를 넣고 except ValueError:로 잡으면 프로그램이 죽는 대신 원하는 처리를 할 수 있다. 

try:
    id = int(input("ID: ").strip())
except ValueError:
    print("숫자를 입력하세요.")
    id = None  # 또는 continue, return 등 — 상황에 맞게 뒤처리

지금 코드의 문제 지점

notes_app.py에 이런 줄이 두 곳 있다:

# 3번(Update)
id = int(input("Enter the ID of the note to update: ").strip())

# 4번(Delete) 1번 서브메뉴
id = find_note_by_id(notes, int(input("Enter the ID of the note to delete: ").strip()))

둘 다 int(...)이 try 없이 바로 실행된다. 숫자가 아닌 값을 넣으면 ValueError가 그대로 튀어나와 프로그램 전체가 멈춘다 — 다른 메뉴 항목이나 아직 저장 안 된 변경사항까지 전부 날아간다.

Primary source Python 공식 튜토리얼 — Handling Exceptions — try/except가 여러 종류의 에러를 각각 다르게 처리하는 방법(except를 여러 개 쓰는 것 포함)까지 확인해봐.

확인 퀴즈

1. int("12a")를 실행하면 어떤 일이 일어날까?
2. try 블록 안의 코드에서 except에 적은 종류의 에러가 나면?
3. try/except로 ValueError를 잡지 않으면 지금 코드에서 무슨 일이 생기나?

직접 해보기

notes_app.py에서 진행한다. 한 곳씩 고치고 바로 실행해서 확인한다:

  1. 3번(Update)의 id = int(input(...).strip()) 줄을 try/except ValueError로 감싼다. except 블록에서는 무엇을 해야 할까? — 에러 메시지를 출력하고, 이후의 find_note_by_id 호출로 넘어가면 안 된다는 걸 생각해보자(continue를 쓸 수도 있다 — while 루프의 다음 반복으로 바로 넘어가는 문법인데, 필요하면 물어봐도 된다)
  2. 실제로 3번을 골라서 "abc" 같은 값을 넣어보고, 프로그램이 안 죽고 메시지만 뜨는지 확인한다
  3. 같은 패턴을 4번(Delete)의 1번 서브메뉴에도 적용한다
  4. 고친 뒤 정상적인 ID(숫자)를 넣었을 때도 여전히 잘 동작하는지 확인한다 — 예외 처리를 추가해도 정상 경로가 깨지면 안 된다

막히면 정답을 바로 묻기보다, "지금 뭐가 안 되는지"와 "왜 그런 것 같은지"부터 말해보자. 그게 이 폴더의 핵심 학습 목표(에러 읽는 법)다.
