가상환경(venv)과 pip — 프로젝트별로 패키지 나눠 쓰기

지금까지는 파이썬 표준 기능(json, 클래스 등)만 썼다. 하지만 ai-dev-team에서는 Anthropic Agent SDK처럼 파이썬에 기본으로 없는 외부 패키지를 설치해서 써야 한다. 문제는 컴퓨터 전체에 패키지를 깔면 프로젝트마다 필요한 버전이 달라질 때 충돌한다는 것 — 예를 들어 ai-dev-team에서 실제로 설치하게 될 claude-agent-sdk도 나중에 다른 프로젝트와 버전이 겹칠 수 있다 — 가상환경(virtual environment)은 프로젝트별로 "이 프로젝트만의 파이썬 + 패키지 모음"을 분리해두는 상자다.

왜 필요할까? ai-dev-team 1단계-v1에서 Agent SDK를 설치할 때, 이 프로젝트만의 가상환경이 없으면 다른 프로젝트의 패키지 버전과 충돌하거나 시스템 파이썬을 오염시킬 수 있다. 가상환경을 만드는 습관은 그때 자연스럽게 첫 단계가 된다.

핵심 개념 — 세 가지 명령어

  • python3 -m venv .venv — 현재 폴더에 .venv라는 이름의 가상환경(전용 파이썬 + 빈 패키지 상자)을 새로 만든다.
  • source .venv/bin/activate — 지금 터미널이 그 가상환경의 파이썬을 쓰도록 전환한다. 활성화되면 프롬프트 앞에 (.venv)가 붙는다.
  • pip install 패키지이름 — 활성화된 가상환경 안에 패키지를 설치한다. 시스템 전역이 아니라 .venv 폴더 안에만 저장된다.

가상환경을 껐다 켜는 것뿐, 새로운 문법이 아니다 — 터미널에서 "지금 어떤 파이썬을 쓸지" 스위치를 바꾸는 것에 가깝다.

Primary source Python 공식 문서 — venv: Creation of virtual environments — 가상환경이 정확히 뭘 하는지 공식 설명을 확인해봐.

확인 퀴즈

2. 가상환경을 새로 만드는 명령어는?
3. 활성화 후 pip install로 설치한 패키지는 어디에 저장되나?

직접 해보기

터미널에서 python-basics 폴더 안에 있는 상태로 진행한다:

  1. python3 -m venv .venv — 가상환경을 만든다
  2. source .venv/bin/activate — 활성화한다. 프롬프트 앞에 (.venv)가 보이는지 확인
  3. which python — 지금 쓰는 파이썬이 .venv 안의 것인지 경로로 확인
  4. pip install claude-agent-sdk — ai-dev-team에서 실제로 쓸 Anthropic Claude Agent SDK를 설치해본다
  5. pip list — claude-agent-sdk가 설치 목록에 뜨는지 확인
  6. deactivate — 가상환경을 빠져나온다. 프롬프트에서 (.venv)가 사라지는지 확인

.venv 폴더는 용량이 크고 사람마다 경로가 달라서 git으로 관리하지 않는다. 실습 후 .gitignore에 .venv/ 한 줄을 추가해두자.
