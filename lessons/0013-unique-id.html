고유 ID — title 중복 문제를 근본적으로 해결하기

레슨 9~10 사이에 title이 같은 노트가 여러 개면 항상 헷갈린다는 걸 스스로 발견했었다. 그때는 "찾은 걸 다 모아서 번호를 보여주고 고르게" 하는 방식(find_all_by_title + 리스트 인덱스)으로 넘어갔는데, 이건 매번 검색 결과를 다시 번호 매기는 임시방편이다. 진짜 해결책은 노트마다 절대 바뀌지 않고 절대 겹치지 않는 값 — ID — 를 하나씩 붙여주는 것이다.

왜 필요할까? title은 사용자가 아무 때나 똑같이 입력할 수 있어서 식별자로 못 쓴다. ID는 "이 노트가 정확히 어떤 노트인지" 흔들림 없이 가리키는 값이다. 데이터베이스의 기본 키(primary key), 그리고 나중에 Pydantic 모델에서 자주 보게 될 id: int 필드도 같은 개념이다.

핵심 개념 — 다음 ID를 스스로 계산하기

가장 간단한 방법은 "지금까지 나온 것 중 가장 큰 ID + 1"을 새 ID로 쓰는 것이다. notes가 비어있으면 1부터 시작한다. 이렇게 하면 중간에 노트를 지워도 ID가 절대 겹치지 않는다 (반대로 len(notes) + 1을 쓰면, 지운 뒤 새로 추가할 때 이미 썼던 ID가 재사용돼서 겹칠 수 있다 — 왜 그런지 직접 해보기에서 확인해보자). 

def next_id(notes):
    if not notes:
        return 1
    ids = []
    for n in notes:
        ids.append(n["id"])
    return max(ids) + 1

이미 알고 있는 것만 썼다 — for로 순회하며 리스트에 모으고(레슨 10의 find_all_by_title과 같은 패턴), 파이썬 내장 함수 max()로 가장 큰 값을 구한다.

Primary source Python 공식 문서 — max() — 여러 값 중 가장 큰 값을 구하는 내장 함수의 정확한 동작을 확인해봐.

확인 퀴즈

1. ID로 title 대신 써야 하는 이유는?
2. len(notes) + 1을 새 ID로 쓰면 안 되는 이유는?
3. notes가 빈 리스트일 때 next_id(notes)는 무엇을 반환해야 하나?

직접 해보기

notes.py에서 진행한다:

  1. next_id(notes) 함수를 추가한다 — 위 코드를 참고해서 직접 타이핑해본다
  2. add_note를 수정해서, 새 노트를 만들 때 "id": next_id(notes)를 같이 넣는다
  3. notes_app.py를 실행해서 노트를 두세 개 추가하고, notes.json을 열어 각 노트에 서로 다른 id가 붙었는지 확인한다
  4. 노트 하나를 삭제한 뒤 새 노트를 추가해본다 — 방금 지운 노트의 ID가 재사용되지 않는지 확인한다
  5. (선택, 시간이 남으면) len(notes) + 1로 바꿔서 같은 삭제→추가 테스트를 해보고, 왜 ID가 겹치는지 직접 눈으로 확인한 뒤 다시 max() 버전으로 되돌린다

아직 find/delete 메뉴가 title 기준인 것은 그대로 둔다 — 오늘은 "ID를 만들어서 붙이는 것"까지만. ID로 검색·삭제하도록 메뉴를 바꾸는 건 다음 세션 후보로 남겨두자.
