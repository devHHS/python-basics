노트 수정하기 — 찾은 딕셔너리를 직접 바꾸기

지금까지 노트를 추가(1)하고, 찾고(2), 지울(3) 수 있어. 그런데 제목은 맞는데 내용에 오타가 있으면? 지금은 지우고 다시 추가하는 수밖에 없어. 이번 레슨에서 "4. 수정"을 메뉴에 추가해서, 노트를 찾은 다음 그 내용만 바꾸는 방법을 배운다.

왜 필요할까? 지우고 다시 만드는 것과 "있는 걸 그대로 두고 일부만 바꾸는 것"은 다른 동작이야. 나중에 ai-dev-team에서 에이전트가 "기존 작업 결과를 갱신"해야 할 때(전체를 새로 만들지 않고) 바로 이 패턴을 쓰게 된다.

핵심 개념 — find_note로 찾은 건 "복사본"이 아니다

find_note가 뭘 돌려주는지 다시 보자: 

def find_note(notes, title):
    for n in notes:
        if n["title"] == title:
            return n
    return None

여기서 n은 notes 리스트 안에 있는 바로 그 딕셔너리야. 복사본이 아니야. 그래서 n을 바꾸면 notes 리스트 안의 원본도 같이 바뀐다: 

n = find_note(notes, "장보기")
n["content"] = "우유, 계란"
print(notes)  # notes 안의 "장보기" 노트도 이미 바뀌어 있다

왜 이렇게 될까? 딕셔너리는 변수에 "값 자체"가 아니라 "어디 있는지 가리키는 것"이 담긴다. n과 notes 리스트 속 그 자리는 같은 딕셔너리를 가리키고 있어서, 어느 쪽으로 접근해도 결국 같은 물건을 만지는 거야. 이런 성질을 흔히 "mutable(변경 가능)"이라고 부른다.

Primary source Python 공식 튜토리얼 — Dictionaries — 딕셔너리가 키로 값을 저장하고 바꾸는 기본 동작을 확인해봐.

확인 퀴즈

1. find_note(notes, title)이 돌려주는 n은 무엇일까?
2. 찾은 노트 n의 내용을 새 값으로 바꾸는 코드는?
3. update_note가 제목을 못 찾았을 때 뭘 리턴해야 delete_note에서 있었던 버그를 반복하지 않을까?

직접 해보기

notes_app.py에 "4. 수정"을 추가해보자:

  1. find_note 아래에 update_note(notes, title, new_content) 함수를 만든다
  2. 안에서 find_note(notes, title)로 노트를 찾아 변수(예: n)에 담는다
  3. n is None이면 그대로 None을 리턴한다 (레슨 8 이전에 고친 delete_note 버그를 다시 만들지 않도록)
  4. 찾았으면 n["content"] = new_content로 바꾸고, n을 리턴한다
  5. 메뉴 문자열과 elif 사슬에 "4. 수정"을 끼워 넣는다 — 기존 "4. 종료"는 "5. 종료"로 밀어야 한다
  6. choice == "4" 블록에서 title과 새 내용을 input()으로 받고, update_note를 호출한 뒤 결과가 None인지 확인해서 "찾지 못했습니다" 또는 "수정했습니다" 메시지를 찍는다

힌트: 찾기나 삭제에서 썼던 found = ... / if found is None: 패턴을 그대로 재사용하면 된다. 함수 이름과 안에서 하는 일만 다르다.
